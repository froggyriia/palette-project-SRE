# Отчёт: метрики приложения в VictoriaMetrics

## Стек

- **Приложение:** бэкенд на Python 3.12 + FastAPI, PostgreSQL 16, фронтенд React + nginx; развёрнуто в minikube (манифесты в [`k8s/`](../k8s)).
- **Хранилище метрик:** VictoriaMetrics single-node, Helm-чарт `vm/victoria-metrics-single`, namespace `monitoring`. Значения чарта — [`k8s/monitoring/values.yaml`](../k8s/monitoring/values.yaml).
- **Модель сбора:** pull. VictoriaMetrics сама опрашивает `/metrics` у подов каждые 15 секунд.
- **Формат:** OpenMetrics / Prometheus text format.

## Service discovery

Таргеты находятся автоматически: задача `kubernetes-pods` в [`k8s/monitoring/values.yaml`](../k8s/monitoring/values.yaml) получает список подов из API Kubernetes и оставляет поды с аннотацией `prometheus.io/scrape: "true"`. Порт и путь берутся из аннотаций `prometheus.io/port` и `prometheus.io/path`.

| Под | Аннотации | Что отдаёт |
|---|---|---|
| `backend` ([`k8s/30-backend.yaml`](../k8s/30-backend.yaml)) | port `9100`, path `/metrics` | метрики рантайма, HTTP и бизнес-метрики |
| `db` ([`k8s/10-db.yaml`](../k8s/10-db.yaml)) | port `9187`, path `/metrics` | метрики PostgreSQL от postgres-exporter |

Остальные задачи сбора (VictoriaMetrics, API-сервер, узлы, cAdvisor) взяты из инструкции VictoriaMetrics.

## Экспортеры

**Метрики рантайма Python** — стандартные коллекторы библиотеки `prometheus_client`: `process_cpu_seconds_total`, `process_resident_memory_bytes`, `process_open_fds`, `python_gc_*`, `python_info`.

**Метрики фреймворка FastAPI** — библиотека `prometheus-fastapi-instrumentator`: `http_requests_total{handler, method, status}`, `http_request_duration_seconds`, `http_request_size_bytes`, `http_response_size_bytes`. Запросы к `/health` исключены.

Метрики отдаются отдельным HTTP-сервером на порту 9100 ([`backend/app/metrics.py`](../backend/app/metrics.py)). Порт объявлен в контейнере, но не входит в Service `backend`, поэтому доступен только изнутри кластера, без авторизации.

**Метрики PostgreSQL** — `postgres-exporter` (`quay.io/prometheuscommunity/postgres-exporter`), добавлен вторым контейнером в под `db`. Контейнеры пода делят сеть, экспортер подключается к базе по `localhost:5432` с учётными данными из Secret `palette-secret`. Основные метрики: `pg_up`, `pg_stat_database_numbackends`, `pg_stat_database_xact_commit`, `pg_database_size_bytes`.

## Бизнес-метрики

Все бизнес-метрики — счётчики (Counter), объявлены в [`backend/app/metrics.py`](../backend/app/metrics.py), увеличиваются в обработчиках [`palettes.py`](../backend/app/routers/palettes.py) и [`auth.py`](../backend/app/routers/auth.py) после успешного выполнения операции.

| Метрика | Метки | Что считает |
|---|---|---|
| `palette_generated_total` | `scheme` | палитры, сгенерированные по цветовой схеме (`complementary`, `analogous`, `triadic`, `tetradic`) |
| `palette_saved_total` | `scheme`, `owner` (`user`/`guest`) | палитры, сохранённые через `POST /palettes` |
| `palette_deleted_total` | — | удалённые палитры |
| `palette_exported_total` | `format` (`json`, `css`, `scss`, `tailwind`) | экспорт палитр по формату |
| `auth_login_total` | `result` (`success`/`failure`) | попытки входа |
| `user_registered_total` | — | регистрации пользователей |

Значения меток ограничены фиксированным набором: неизвестный тип схемы записывается как `custom`, чтобы число временных рядов не росло.

Тесты на счётчики — [`backend/tests/test_metrics.py`](../backend/tests/test_metrics.py).

## Проверка сбора

```sh
kubectl get pods -n monitoring
kubectl port-forward svc/vmsingle-victoria-metrics-single-server -n monitoring 8428:8428
curl "http://localhost:8428/api/v1/query?query=up"
curl "http://localhost:8428/api/v1/query?query=palette_generated_total"
curl "http://localhost:8428/api/v1/query?query=pg_up"
```

Список таргетов и их состояние: `http://localhost:8428/targets`.
