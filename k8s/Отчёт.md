# Отчёт: запуск приложения в minikube

## Использованные абстракции Kubernetes

| Абстракция | Манифест | Назначение |
|---|---|---|
| ConfigMap `palette-config` | [`00-config.yaml`](00-config.yaml) | Нечувствительная конфигурация: `CORS_ORIGINS`, `VITE_API_URL`, `PORT`, имя БД. |
| Secret `palette-secret` | [`00-config.yaml`](00-config.yaml) | Учётные данные PostgreSQL, `DATABASE_URL`, `JWT_SECRET`. |
| StatefulSet `db` + PVC (`volumeClaimTemplates`) | [`10-db.yaml`](10-db.yaml) | PostgreSQL 16 с постоянным томом 1 Gi; данные сохраняются при перезапуске пода. |
| Service `db` (ClusterIP) | [`10-db.yaml`](10-db.yaml) | Стабильное DNS-имя `db:5432` для бэкенда. |
| Job `migrate` | [`20-migrate.yaml`](20-migrate.yaml) | Разовая задача: `alembic upgrade head` из образа бэкенда, повторяется до готовности БД. |
| Deployment `backend` (2 реплики) | [`30-backend.yaml`](30-backend.yaml) | FastAPI/uvicorn; `readinessProbe` и `livenessProbe` на `/health`. |
| Service `backend` (ClusterIP) | [`30-backend.yaml`](30-backend.yaml) | Балансировка запросов между репликами бэкенда. |
| Deployment `frontend` (2 реплики) | [`40-frontend.yaml`](40-frontend.yaml) | nginx со статикой React; `readinessProbe` на `/`. |
| Service `frontend` (ClusterIP) | [`40-frontend.yaml`](40-frontend.yaml) | Балансировка между репликами фронтенда. |

Образы собираются в Docker-демоне minikube (`eval $(minikube docker-env)`) командой `docker build`, поэтому в манифестах указан `imagePullPolicy: Never`. Сборку и применение манифестов выполняет [`deploy.sh`](deploy.sh). Dockerfile сервисов: [`backend/Dockerfile`](../backend/Dockerfile), [`frontend/Dockerfile`](../frontend/Dockerfile).

## Взаимодействие сервисов

```
Браузер ──(port-forward :5173)──> Service frontend ──> Pod frontend (nginx, статика)
   │
   └──(port-forward :8000)──> Service backend ──> Pod backend ×N (FastAPI)
                                                        │
                                                        └──> Service db ──> Pod db (PostgreSQL + PVC)
Job migrate ──> Service db   (создание схемы)
```

- Фронтенд выполняется в браузере и обращается к API напрямую по адресу из `VITE_API_URL`. Адрес берётся из ConfigMap и записывается в `env-config.js` при старте контейнера ([`docker-entrypoint.sh`](../frontend/docker-entrypoint.sh)). Под nginx отдаёт только статику, запросов к бэкенду изнутри кластера он не делает.
- Бэкенд подключается к PostgreSQL по DNS-имени сервиса `db` через `DATABASE_URL` из Secret.
- Реплики бэкенда не хранят состояние (JWT, данные в БД), поэтому Service распределяет запросы между ними произвольно.
- Внутри кластера сервисы доступны по именам `db`, `backend`, `frontend`. Снаружи доступ к `frontend` и `backend` организован через `kubectl port-forward` (порты 5173 и 8000). Адреса `localhost` совпадают с `CORS_ORIGINS` и `VITE_API_URL` в ConfigMap.

## Запуск

```sh
minikube start
./k8s/deploy.sh                      # сборка образов и kubectl apply -f k8s/
kubectl get pods
kubectl scale deployment backend --replicas=4
kubectl scale deployment frontend --replicas=3
kubectl port-forward svc/frontend 5173:80 &
kubectl port-forward svc/backend 8000:8000 &
# UI: http://localhost:5173
```
