# Отчёт: SLI, SLO и SLA

## Выбранные метрики

| Метрика | Источник | Что показывает |
|---|---|---|
| `http_requests_total{status}` | бэкенд, `prometheus-fastapi-instrumentator` | число HTTP-запросов по кодам ответа |
| `http_request_duration_highr_seconds` | бэкенд, `prometheus-fastapi-instrumentator` | гистограмма времени ответа, корзины от 10 мс до 60 с |
| `prober_success` | пробер, [`prober/prober.py`](../prober/prober.py) | 1, если последняя проверка пользовательского сценария прошла, иначе 0 |
| `prober_duration_seconds` | пробер | длительность последней проверки |

Метрики собираются VictoriaMetrics по аннотациям `prometheus.io/*` раз в 15 секунд (см. прошлое задание).

### Пробер

Пробер — отдельный Deployment ([`k8s/50-prober.yaml`](../k8s/50-prober.yaml)), который каждые 10 секунд выполняет основной сценарий приложения через Service `backend`:

1. `POST /palettes/generate` — ожидается ответ 201 и палитра из трёх цветов;
2. `DELETE /palettes/{id}` — ожидается 204, тестовая палитра удаляется.

Проверка успешна, только если оба шага прошли в пределах таймаута 3 с. Пробер создаёт постоянный трафик, поэтому SLI считаются и при отсутствии пользователей.

## SLI

Окно `W` для SLI в демонстрации — 1 минута.

**SLI-1. Доступность API (Request Based)** — доля запросов без ошибки сервера. Ответы 4xx считаются успешными: это ошибки клиента.

```
SLI_avail = успешные запросы / все запросы
          = sum(rate(http_requests_total{app="backend", status!~"5.."}[1m]))
          / sum(rate(http_requests_total{app="backend"}[1m]))
```

**SLI-2. Задержка (Request Based)** — доля запросов, обработанных быстрее 250 мс.

```
SLI_latency = запросы быстрее 250 мс / все запросы
            = sum(rate(http_request_duration_highr_seconds_bucket{app="backend", le="0.25"}[1m]))
            / sum(rate(http_request_duration_highr_seconds_count{app="backend"}[1m]))
```

**SLI-3. Работоспособность сценария (Time Based)** — доля «хороших» минут. Минута хорошая, если все проверки пробера в ней успешны.

```
хорошая минута     = min_over_time(prober_success[1m]) == 1
SLI_probe(окно T)  = хорошие минуты / все минуты
                   = avg_over_time(min_over_time(prober_success[1m])[T:1m])
```

## SLO

| SLO | Целевое значение | Окно |
|---|---|---|
| Доступность API | SLI_avail ≥ 99% | 30 дней (в демонстрации 30 минут) |
| Задержка | SLI_latency ≥ 95% | 30 дней (в демонстрации 30 минут) |
| Работоспособность сценария | SLI_probe ≥ 99% | 30 дней (в демонстрации 30 минут) |

Выполнение SLO за окно (пример для доступности, окно 30 минут):

```
SLO_avail = sum(increase(http_requests_total{app="backend", status!~"5.."}[30m]))
          / sum(increase(http_requests_total{app="backend"}[30m]))      ≥ 0.99
```

Остаток бюджета ошибок — доля допустимых ошибок, которая ещё не израсходована:

```
error_budget = 1 - (1 - SLO_avail) / (1 - 0.99)
```

Значение 1 означает, что ошибок не было; 0 и ниже — SLO нарушен.

## SLA

SLA — внешнее обязательство перед пользователями. Пороги ниже SLO, чтобы у команды был запас на реакцию до нарушения обязательств.

**SLA приложения:** доступность сервиса не менее 98% за календарный месяц. Доступность за месяц — минимум из двух показателей: доли успешных запросов (SLI_avail) и доли хороших минут (SLI_probe).

```
SLA = min(SLI_avail(месяц), SLI_probe(месяц)) ≥ 0.98
```

В демонстрации (окно 30 минут):

```
min(
  label_set(
    sum(increase(http_requests_total{app="backend", status!~"5.."}[30m]))
    / sum(increase(http_requests_total{app="backend"}[30m])),
    "sli", "availability")
  or
  label_set(avg_over_time(min_over_time(prober_success[1m])[30m:1m]), "sli", "probe")
)
```

## Изменения приложения для демонстрации

**Внедрение сбоев** — [`backend/app/faults.py`](../backend/app/faults.py). Middleware управляется переменными окружения и подключён до инструментатора, поэтому внедрённые ошибки и задержки попадают в метрики. Эндпоинт `/health` не затрагивается, пробы Kubernetes продолжают работать.

| Переменная | Действие |
|---|---|
| `FAULT_ERROR_RATE` | доля запросов, на которые бэкенд отвечает 500 (0–1) |
| `FAULT_DELAY_MS` | задержка в миллисекундах для каждого запроса |

По умолчанию обе равны 0 ([`k8s/30-backend.yaml`](../k8s/30-backend.yaml)).

**Сценарии на скринкасте:**

| Этап | Команда | Ожидаемый эффект |
|---|---|---|
| Деградация | `kubectl set env deployment/backend FAULT_DELAY_MS=400 FAULT_ERROR_RATE=0.3` | SLI_latency падает почти до 0, SLI_avail ≈ 70%, SLI_probe = 0, SLA снижается |
| Отказ базы данных | `kubectl scale statefulset db --replicas=0` | запросы к палитрам возвращают 500, SLI_avail и SLI_probe падают до 0 |
| Восстановление | `kubectl set env deployment/backend FAULT_DELAY_MS=0 FAULT_ERROR_RATE=0`, `kubectl scale statefulset db --replicas=1` | SLI возвращаются к 100% в течение окна SLI; SLA за 30 минут восстанавливается постепенно |

**Прочие изменения:**
- в VictoriaMetrics `search.latencyOffset` уменьшен до 5 секунд ([`k8s/monitoring/values.yaml`](../k8s/monitoring/values.yaml)), чтобы графики быстрее реагировали на изменения;
- пробер собран в отдельный образ: [`prober/Dockerfile`](../prober/Dockerfile).

## Графики

Графики строятся в vmui (`http://localhost:8428/vmui`). На каждом графике два запроса: SLI и горизонтальная линия SLO (например, `0.99`).
