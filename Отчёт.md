# Отчёт

Репозиторий: https://github.com/froggyriia/palette-project-SRE (ветка `master`)

## Доменная область приложения

Веб-приложение для генерации и сохранения цветовых палитр — инструмент для дизайнеров и разработчиков, которым нужно быстро подобрать сочетающиеся цвета для интерфейса.

Пользователь выбирает базовый цвет и цветовую схему (комплементарная, аналоговая, триада, тетрада). Приложение по правилам теории цвета генерирует остальные цвета палитры, показывает их на цветовом колесе и проверяет контраст между ними по стандарту WCAG. Готовую палитру можно сохранить в аккаунт и экспортировать в CSS/SCSS/Tailwind/JSON. Без регистрации приложением можно пользоваться как гостем; палитры сохраняются только для залогиненных пользователей.

## Стек реализации

**Бэкенд:** Python 3.12, FastAPI 0.115, SQLAlchemy 2.0 + Alembic (миграции), PostgreSQL 16, JWT (PyJWT) для аутентификации, bcrypt (passlib) для хэширования паролей. Конфигурация — pydantic-settings.

**Фронтенд:** React 18 + Vite 5, Tailwind CSS. Взаимодействие с бэкендом — через fetch к REST API.

**Инфраструктура:** Docker + docker-compose, три сервиса (`db`, `backend`, `frontend`), nginx раздаёт собранную статику фронтенда.

**Тесты:** pytest, 44 теста на бэкенде — доменная логика (цветовая теория, контраст) и сверка формул фронтенда с бэкендом через общий JSON-фикстур.

## Основные сущности доменной области

- **User** — пользователь: email, хэш пароля. [`backend/app/models.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/models.py#L14-L23)
- **Palette** — палитра: имя, базовый цвет, тип схемы, опциональная привязка к пользователю (`user_id` может быть `null` — гостевая палитра). [`backend/app/models.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/models.py#L26-L41)
- **Color** — один цвет внутри палитры: hex-код и позиция. [`backend/app/models.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/models.py#L44-L54)

Связи: `User 1—N Palette`, `Palette 1—N Color`, с каскадным удалением.

Отдельно от моделей БД — чистая доменная логика без FastAPI/SQL, тестируемая изолированно:
- [`backend/app/color_theory.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/color_theory.py) — переводы hex↔HSL, построение схем поворотом оттенка.
- [`backend/app/contrast.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/contrast.py) — расчёт контраста по WCAG (относительная яркость, коэффициент контраста, порог AA).
- [`backend/app/export.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/export.py) — сериализация палитры в CSS/SCSS/Tailwind-конфиг/JSON.

## Соответствие методологии 12 факторов

### I. Codebase — одна кодовая база

Один git-репозиторий на бэкенд и фронтенд, история коммитов разбита по этапам разработки. Деплой собирается из этого же репозитория.

### II. Dependencies — явное объявление зависимостей

Зависимости бэкенда зафиксированы с точными версиями в [`backend/requirements.txt`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/requirements.txt) (`fastapi==0.115.0`, `sqlalchemy==2.0.35` и т.д.). Отдельный [`requirements-dev.txt`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/requirements-dev.txt) — только для тестов. У фронтенда — `package.json` с закоммиченным `package-lock.json`, версия каждого пакета детерминирована. Docker-сборка ([`backend/Dockerfile`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/Dockerfile), [`frontend/Dockerfile`](https://github.com/froggyriia/palette-project-SRE/blob/master/frontend/Dockerfile)) ставит зависимости с нуля в изолированный образ.

### III. Config — конфигурация через окружение

Параметры (строка подключения к БД, секрет для JWT, список CORS-источников, порт) читаются из переменных окружения через `pydantic-settings` — [`backend/app/config.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/config.py#L1-L20). В коде — только дефолты для локальной разработки. Секреты (`.env`) в `.gitignore`, в репозитории — `.env.example`.

### IV. Backing services — сервисы как подключаемые ресурсы

PostgreSQL подключается по `DATABASE_URL`, обычной connection-строке. Смена БД (другой хост, Supabase, RDS) — смена переменной окружения, без правки кода.

### V. Build, release, run — разделение стадий

Docker-сборка (`build`) даёт неизменный артефакт. Конфигурация под конкретное окружение (release) внедряется отдельно, в момент запуска контейнера, через переменные окружения. Для фронтенда это отдельная задача: `VITE_API_URL` раньше внедрялся в файлы на этапе `npm run build`, то есть смешивал build и release. Решение — [`frontend/docker-entrypoint.sh`](https://github.com/froggyriia/palette-project-SRE/blob/master/frontend/docker-entrypoint.sh) генерирует `env-config.js` из переменной окружения контейнера при старте. Один собранный образ разворачивается с разным адресом бэкенда без пересборки.

### VI. Processes — приложение как stateless-процесс

Бэкенд не хранит сессии в памяти процесса. Аутентификация — через JWT: весь нужный контекст в самом токене — [`backend/app/security.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/security.py). Любой запрос может обработать любой инстанс процесса. Состояние (палитры, пользователи) хранится в БД.

### VII. Port binding — экспорт через привязку к порту

Приложение само поднимает HTTP-сервер (uvicorn) на порту, заданном переменной `PORT` — [`backend/Dockerfile`, строка 19](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/Dockerfile#L19).

### VIII. Concurrency — масштабирование через процессы

Число рабочих процессов uvicorn задаётся переменной `WEB_CONCURRENCY`, по умолчанию 1 — [`backend/Dockerfile`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/Dockerfile#L15-L19). Это возможно благодаря пункту VI: приложение stateless, процессы не делят общего состояния в памяти.

### IX. Disposability — быстрый старт и корректная остановка

При старте приложение не делает ничего тяжёлого, готово принимать трафик сразу. При остановке (`SIGTERM`, который uvicorn переводит в shutdown-событие) явно закрывается пул соединений к БД — [`backend/app/main.py`, `lifespan`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/main.py#L13-L23).

### X. Dev/prod parity — сходство окружений

Локальная разработка и сборка для деплоя используют один и тот же docker-compose с той же версией PostgreSQL (16-alpine). Образ фронтенда собирается на Node той же мажорной версии (22), что установлена локально — [`frontend/Dockerfile`, строки 1–5](https://github.com/froggyriia/palette-project-SRE/blob/master/frontend/Dockerfile#L1-L5). Расхождение между окружениями минимально.

### XI. Logs — логи как поток событий

Приложение не пишет логи в файлы. Uvicorn по умолчанию пишет access/error-логи в stdout/stderr, сбор и агрегация логов — задача окружения выполнения. В `backend/app` нет ни одного `logging.FileHandler`.

### XII. Admin processes — административные задачи как разовые процессы

Миграции схемы БД выполняются через Alembic (`alembic upgrade head`) как отдельная одноразовая команда, в том же образе и с тем же кодом, что и сам сервис. Конфигурация Alembic берёт `DATABASE_URL` из тех же настроек приложения — [`backend/migrations/env.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/migrations/env.py).

## Примечания

Есть намеренное дублирование логики: цветовая схема считается в двух местах независимо — в бэкенде, [`backend/app/color_theory.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/color_theory.py), и во фронтенде, [`frontend/src/utils/color.js`](https://github.com/froggyriia/palette-project-SRE/blob/master/frontend/src/utils/color.js). Причина — цветовое колесо и превью палитры на фотографии яблока должны обновляться вживую при перетаскивании, без запроса к API на каждое движение курсора; фронтенд сам пересчитывает формулу схемы.

Риск такого дублирования — расхождение формул на двух языках. Он покрыт тестом: [`shared/gen_color_fixtures.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/shared/gen_color_fixtures.py) генерирует набор эталонных пар вход/выход из бэкенда, [`backend/tests/test_color_fixture_consistency.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/tests/test_color_fixture_consistency.py) проверяет бэкенд против этого набора, [`frontend/scripts/check-color-fixtures.mjs`](https://github.com/froggyriia/palette-project-SRE/blob/master/frontend/scripts/check-color-fixtures.mjs) проверяет фронтенд против того же набора независимо. Тест уже находил реальное расхождение — Python и JavaScript по-разному округляют дробные значения — оно исправлено.
