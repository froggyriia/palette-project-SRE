# Отчёт

Репозиторий: https://github.com/froggyriia/palette-project-SRE (ветка `master`)

## Доменная область приложения

Веб-приложение для генерации и сохранения цветовых палитр — инструмент для дизайнеров/разработчиков, которым нужно быстро подобрать сочетающиеся цвета для интерфейса.

Пользователь выбирает базовый цвет и цветовую схему (комплементарная, аналоговая, триада, тетрада), приложение по правилам теории цвета генерирует остальные цвета палитры, показывает их на цветовом колесе и проверяет контраст между ними по стандарту WCAG (нужно ли для доступности текста). Готовую палитру можно сохранить в аккаунт, экспортировать в CSS/SCSS/Tailwind/JSON. Без регистрации приложением можно пользоваться как гостем — палитры сохраняются только для залогиненных пользователей.

## Стек реализации

**Бэкенд:** Python 3.12, FastAPI 0.115, SQLAlchemy 2.0 + Alembic (миграции), PostgreSQL 16, аутентификация через JWT (PyJWT) и хэширование паролей bcrypt (passlib). Конфигурация — pydantic-settings.

**Фронтенд:** React 18 + Vite 5, Tailwind CSS. Общение с бэкендом — через fetch к REST API.

**Инфраструктура:** Docker + docker-compose (три сервиса: `db`, `backend`, `frontend`), nginx как раздатчик собранной статики фронтенда.

**Тесты:** pytest — 44 теста на бэкенде (чистая доменная логика: цветовая теория, контраст, сверка формул фронтенда с бэкендом через общий JSON-фикстур).

## Основные сущности доменной области

- **User** — пользователь: email, хэш пароля. [`backend/app/models.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/models.py#L14-L23)
- **Palette** — палитра: имя, базовый цвет, тип схемы, опциональная привязка к пользователю (`user_id` может быть `null` — тогда палитра гостевая). [`backend/app/models.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/models.py#L26-L41)
- **Color** — один цвет внутри палитры: hex-код и позиция (порядок в палитре). [`backend/app/models.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/models.py#L44-L54)

Связи: `User 1—N Palette`, `Palette 1—N Color`, с каскадным удалением (удалили палитру — удалились и её цвета).

Отдельно от моделей БД — чистая доменная логика без FastAPI/SQL, тестируемая изолированно:
- [`backend/app/color_theory.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/color_theory.py) — переводы hex↔HSL и построение схем (комплементарная/аналоговая/триада/тетрада) поворотом оттенка.
- [`backend/app/contrast.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/contrast.py) — расчёт контраста по WCAG (относительная яркость, коэффициент контраста, проверка порога AA).
- [`backend/app/export.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/export.py) — сериализация палитры в CSS/SCSS/Tailwind-конфиг/JSON.

## Соответствие методологии 12 факторов

### I. Codebase — одна кодовая база

Один git-репозиторий на бэкенд и фронтенд, история коммитов разбита по этапам разработки. Деплой (Docker-образы) собирается из этого же репозитория, отдельных копий кода под разные окружения нет.

### II. Dependencies — явное объявление зависимостей

Зависимости бэкенда зафиксированы с точными версиями в [`backend/requirements.txt`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/requirements.txt) (например `fastapi==0.115.0`, `sqlalchemy==2.0.35`) — ничего не подразумевается «уже стоящим в системе». Отдельный [`requirements-dev.txt`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/requirements-dev.txt) — только для тестов, в проде не ставится. У фронтенда — `package.json` + закоммиченный `package-lock.json`, так что версия каждого пакета детерминирована. Сборка в Docker ([`backend/Dockerfile`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/Dockerfile), [`frontend/Dockerfile`](https://github.com/froggyriia/palette-project-SRE/blob/master/frontend/Dockerfile)) ставит зависимости с нуля в изолированный образ.

### III. Config — конфигурация через окружение

Все параметры (строка подключения к БД, секрет для JWT, список CORS-источников, порт) читаются из переменных окружения через `pydantic-settings`, а не зашиты в коде — [`backend/app/config.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/config.py#L1-L20). В коде остались только разумные дефолты для локальной разработки. Секреты (`.env`) в `.gitignore`, в репозитории только `.env.example`.

### IV. Backing services — сервисы как подключаемые ресурсы

PostgreSQL подключается по `DATABASE_URL` — это обычный URL, который можно поменять на другую БД (другой хост, Supabase, RDS и т.п.) без правки кода, просто сменой переменной окружения. Приложение не завязано на то, что БД обязательно локальная.

### V. Build, release, run — разделение стадий

Docker-сборка (`build`) даёт неизменный артефакт; конфигурация (release) внедряется отдельно в момент запуска контейнера через переменные окружения. Для фронтенда это особенно важно: раньше `VITE_API_URL` «запекался» в сборку на этапе `npm run build`, что нарушало бы разделение build/release. Решение — [`frontend/docker-entrypoint.sh`](https://github.com/froggyriia/palette-project-SRE/blob/master/frontend/docker-entrypoint.sh) генерирует `env-config.js` из переменной окружения контейнера **при старте**, а не при сборке — один и тот же собранный образ можно раскатить с разным адресом бэкенда без пересборки.

### VI. Processes — приложение как stateless-процесс

Бэкенд не хранит сессии в памяти процесса — аутентификация через JWT (весь нужный контекст в самом токене), а не через server-side сессии. Любой запрос может обработать любой инстанс процесса — [`backend/app/security.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/security.py). Состояние (палитры, пользователи) живёт только в БД.

### VII. Port binding — экспорт через привязку к порту

Приложение само поднимает HTTP-сервер (uvicorn) на порту, заданном переменной `PORT`, а не полагается на внешний контейнер вроде Apache/mod_wsgi — [`backend/Dockerfile`, строка 19](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/Dockerfile#L19).

### VIII. Concurrency — масштабирование через процессы

Число рабочих процессов uvicorn задаётся переменной `WEB_CONCURRENCY` (по умолчанию 1, чтобы локальная разработка не менялась) — то же место в [`backend/Dockerfile`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/Dockerfile#L15-L19). Это осознанно возможно именно потому, что приложение stateless (пункт VI) — несколько процессов не делят между собой никакого общего состояния в памяти.

### IX. Disposability — быстрый старт и корректная остановка

При старте приложение не делает ничего тяжёлого — готово принимать трафик сразу. При остановке (`SIGTERM`, который uvicorn превращает в shutdown-событие) явно закрывается пул соединений к БД, а не бросается на середине — [`backend/app/main.py`, `lifespan`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/app/main.py#L13-L23).

### X. Dev/prod parity — сходство окружений

Локальная разработка и «прод»-сборка используют один и тот же docker-compose с той же версией PostgreSQL (16-alpine), а образ фронтенда собирается на Node той же мажорной версии (22), что стоит локально — [`frontend/Dockerfile`, строки 1–5](https://github.com/froggyriia/palette-project-SRE/blob/master/frontend/Dockerfile#L1-L5). Расхождение окружений сведено к минимуму — не «на деве SQLite, на проде Postgres».

### XI. Logs — логи как поток событий

Приложение не пишет логи в файлы — uvicorn по умолчанию пишет access/error-логи в stdout/stderr, а дальше их обработка (сбор, агрегация) — забота окружения выполнения, а не самого кода. В `backend/app` намеренно нет ни одного `logging.FileHandler`.

### XII. Admin processes — административные задачи как разовые процессы

Миграции схемы БД выполняются через Alembic (`alembic upgrade head`) как отдельная одноразовая команда в том же образе и с тем же кодом, что и сам сервис — не отдельным скриптом с своей версией зависимостей. Конфигурация Alembic сама берёт `DATABASE_URL` из тех же настроек приложения — [`backend/migrations/env.py`](https://github.com/froggyriia/palette-project-SRE/blob/master/backend/migrations/env.py).
