# Отчёт: распределение трафика 90/10 через Gateway API

Две версии бэкенда (`v1.0.0` и `v2.0.0`) развёрнуты в minikube, у каждой свой ClusterIP Service. Gateway и HTTPRoute (Envoy Gateway) делят трафик весами 90/10. Проверка — три серии по 200 запросов.

## Схема

```
check.sh (curl /version, 200 запросов)
        │ port-forward :8889
        ▼
Envoy-прокси Gateway palette-gateway (namespace envoy-gateway-system)
        │ HTTPRoute palette-split
        ├── weight 90 ──▶ Service backend-v1 (ClusterIP) ──▶ 2 пода v1.0.0 ─┐
        └── weight 10 ──▶ Service backend-v2 (ClusterIP) ──▶ 2 пода v2.0.0 ─┴──▶ PostgreSQL (namespace default)
```

- Все ресурсы задания находятся в namespace `gateway-split`.
- Envoy Gateway и GatewayClass `eg` установлены в предыдущем задании (`k8s/deploy-strategies/setup.sh`). Для Gateway `palette-gateway` контроллер поднимает отдельный Envoy-прокси.
- Обе версии собраны из одного образа `palette-backend:1.1` и различаются только переменной `APP_VERSION`. Эндпоинт `GET /version` возвращает версию и имя пода: `{"version": "v2.0.0", "pod": "backend-v2-..."}`. По нему считаются ответы каждой версии.
- Состояние хранится в PostgreSQL основного приложения, поэтому запрос может обслужить любой под любой версии.

## Развёртывание

```sh
kubectl apply -f k8s/gateway-split/
kubectl rollout status deployment/backend-v1 -n gateway-split
kubectl rollout status deployment/backend-v2 -n gateway-split
./k8s/gateway-split/check.sh
```

Состояние ресурсов:

```
$ kubectl get deploy,svc,gateway,httproute -n gateway-split
NAME                         READY   UP-TO-DATE   AVAILABLE   AGE
deployment.apps/backend-v1   2/2     2            2           115s
deployment.apps/backend-v2   2/2     2            2           114s

NAME                 TYPE        CLUSTER-IP       EXTERNAL-IP   PORT(S)   AGE
service/backend-v1   ClusterIP   10.100.212.254   <none>        80/TCP    115s
service/backend-v2   ClusterIP   10.97.118.194    <none>        80/TCP    114s

NAME                                                CLASS   ADDRESS   PROGRAMMED   AGE
gateway.gateway.networking.k8s.io/palette-gateway   eg                False        115s
```

Gateway принят контроллером (условия `Accepted` и `ResolvedRefs` у слушателя `http` — `True`). `PROGRAMMED False` означает, что у Gateway нет внешнего адреса: в minikube сервис типа LoadBalancer остаётся в `<pending>`. Envoy-прокси при этом работает, запросы к нему идут через `kubectl port-forward`.

## Манифесты

Файлы лежат в [`k8s/gateway-split/`](../k8s/gateway-split).

### Deployment и Service v1 — [`02-backend-v1.yaml`](../k8s/gateway-split/02-backend-v1.yaml)

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend-v1
  namespace: gateway-split
spec:
  replicas: 2
  selector:
    matchLabels:
      app: palette-backend
      version: v1.0.0
  template:
    metadata:
      labels:
        app: palette-backend
        version: v1.0.0
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "9100"
        prometheus.io/path: "/metrics"
    spec:
      containers:
        - name: backend
          image: palette-backend:1.1
          imagePullPolicy: Never
          ports:
            - name: http
              containerPort: 8000
            - name: metrics
              containerPort: 9100
          envFrom:
            - configMapRef: {name: palette-config}
            - secretRef: {name: palette-secret}
          env:
            - name: APP_VERSION
              value: v1.0.0
          readinessProbe:
            httpGet: {path: /ready, port: http}
            initialDelaySeconds: 3
            periodSeconds: 5
          livenessProbe:
            httpGet: {path: /live, port: http}
            initialDelaySeconds: 10
            periodSeconds: 10
          lifecycle:
            preStop:
              exec:
                command: ["sleep", "5"]
          resources:
            requests: {cpu: 25m, memory: 64Mi}
            limits: {memory: 256Mi}
---
apiVersion: v1
kind: Service
metadata:
  name: backend-v1
  namespace: gateway-split
spec:
  type: ClusterIP
  selector:
    app: palette-backend
    version: v1.0.0
  ports:
    - name: http
      port: 80
      targetPort: http
```

### Deployment и Service v2 — [`02-backend-v2.yaml`](../k8s/gateway-split/02-backend-v2.yaml)

Совпадает с v1, кроме имён и версии: `backend-v1` → `backend-v2`, `v1.0.0` → `v2.0.0` в метках, селекторах и `APP_VERSION`.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend-v2
  namespace: gateway-split
spec:
  replicas: 2
  selector:
    matchLabels:
      app: palette-backend
      version: v2.0.0
  template:
    metadata:
      labels:
        app: palette-backend
        version: v2.0.0
    spec:
      containers:
        - name: backend
          image: palette-backend:1.1
          env:
            - name: APP_VERSION
              value: v2.0.0
          # остальные поля — как у v1
---
apiVersion: v1
kind: Service
metadata:
  name: backend-v2
  namespace: gateway-split
spec:
  type: ClusterIP
  selector:
    app: palette-backend
    version: v2.0.0
  ports:
    - name: http
      port: 80
      targetPort: http
```

### Gateway — [`01-gateway.yaml`](../k8s/gateway-split/01-gateway.yaml)

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: palette-gateway
  namespace: gateway-split
spec:
  gatewayClassName: eg
  listeners:
    - name: http
      protocol: HTTP
      port: 80
```

### HTTPRoute 90/10 — [`03-httproute.yaml`](../k8s/gateway-split/03-httproute.yaml)

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: palette-split
  namespace: gateway-split
spec:
  parentRefs:
    - name: palette-gateway
  rules:
    - backendRefs:
        - name: backend-v1
          port: 80
          weight: 90
        - name: backend-v2
          port: 80
          weight: 10
```

Доля backend равна его весу, делённому на сумму весов: v1 — 90 / (90 + 10) = 90%, v2 — 10%.

Namespace, ConfigMap и Secret бэкенда — в [`00-namespace.yaml`](../k8s/gateway-split/00-namespace.yaml).

## Проверка распределения

[`check.sh`](../k8s/gateway-split/check.sh) делает port-forward на Envoy-прокси Gateway, отправляет 200 запросов `GET /version` и считает, сколько ответила каждая версия. Ответ каждого запроса (номер, версия, под) и итог серии записываются в [`results.log`](results.log).

| Серия | v1.0.0 | v2.0.0 |
|---|---|---|
| 1 | 181 (90,5%) | 19 (9,5%) |
| 2 | 177 (88,5%) | 23 (11,5%) |
| 3 | 181 (90,5%) | 19 (9,5%) |
| **Всего, 600 запросов** | **539 (89,8%)** | **61 (10,2%)** |
| Ожидание при весах 90/10 | 540 (90%) | 60 (10%) |

## Вывод

Фактическое распределение соответствует весам 90/10:

- В каждой серии из 200 запросов на v2 пришлось 19–23 запроса при ожидаемых 20. Отклонение доли от 10% — не больше 1,5 процентного пункта.
- Суммарно на 600 запросах — 89,8% / 10,2%, разница с ожиданием в один запрос.

Расхождение внутри серии объясняется тем, что Envoy выбирает backend для каждого запроса случайно с вероятностями, пропорциональными весам. Число ответов v2 в серии из 200 запросов — случайная величина со средним 200 · 0,1 = 20 и стандартным отклонением √(200 · 0,1 · 0,9) ≈ 4,2. Значит, примерно в 95% серий v2 ответит на 12–28 запросов (6–14%). Все три серии находятся в пределах одного стандартного отклонения от среднего, а с ростом числа запросов доля приближается к заданному весу.
